## Project rules
- All TinyFish and AI provider calls go through thin `createServerFn` proxies in `src/lib/tinyfish.functions.ts`; user keys arrive per request and are never stored server-side (BYOK, no backend, no auth).
- Dossier orchestration runs in the browser (`src/lib/run-dossier.ts`) so long agent runs are polled from the client instead of holding a worker request open.
- Coverage is limited to the jurisdictions in `src/lib/sources.ts` (Seattle/King County, San Francisco, New York City). Each record type lists curated official portals, ordered by preference, with numbered agent steps researched from the sites' own help pages. Addresses outside them are rejected after the free geocode, before any TinyFish call. To add a city, add a `Jurisdiction` there and verify each URL/label live with TinyFish Fetch first.
- Agent `output_schema` may only use TinyFish's allowlisted keywords (no `description`); field guidance goes in the goal text. A unit test enforces this.
- The readable report is the main output; JSON and PDF (print) are exports. TinyFish Fetch cross-checks each extracted record on its source page (`seenOnPage`). "Watch" creates TinyFish Monitors on the record pages, and re-checks diff permits and violations against the saved snapshot.
- Build tooling is a plain `vite.config.ts` (TanStack Start + nitro `cloudflare-module` preset, Tailwind, tsconfig paths, React); dev server runs on port 8080.
- Dossier runs live in `src/lib/dossier-runner.ts`, outside the page component. Every change is saved to localStorage with each section's current agent `runId`. Navigating away and back re-attaches; a refresh resumes polling the same runs; a localStorage lock (owner id in sessionStorage) stops other tabs from starting duplicate runs. Only Stop (`RunControl.stop`) cancels runs. A run cancelled from outside does not trigger fallback sources.
- Tests: `npx vitest run` (unit). Live checks: `LIVE=1 npx vitest run src/test/live-dossier.test.ts` hits only Fetch (free); add `LIVE_AGENT=seattle|san-francisco|nyc` for one paid full-dossier run.
- Record status, official-domain filtering and snapshot diffing live as pure functions in `src/lib/dossier-core.ts` with tests; records are never invented — missing data must map to an explicit status.
- Settings, cached dossiers and watches persist in localStorage (`src/lib/storage.ts`) because the project intentionally has no database.
- Shared navigation stays in SiteHeader with a reserved body offset; the landing-page search navigates to the existing dossier page so presentation changes do not duplicate lookup logic.
